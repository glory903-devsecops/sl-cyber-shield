# 7. 시나리오 3: Spring4Shell 다형성 페이로드 및 패치 우회 기반 워터홀 공격

본 시나리오는 관리자의 심리를 악용하는 소셜 엔지니어링에, GitHub에 공개된 최신 Spring4Shell 우회 기법(WAF Bypass, 임시 패치 우회)을 결합한 고도화된 침투 시뮬레이션입니다.

## 7-1. 테스트 환경 및 주요 취약점 정보
* **초기 침투 (Drive-by):** 위장 웹 페이지를 통한 CSRF/AJAX 백그라운드 익스플로잇 실행.
* **코어 취약점 (CVE-2022-22965):** Java 9+ 환경의 `class.module.classLoader` 조작을 통한 Tomcat 웹쉘 드롭.
* **우회 및 연계 취약점:**
  * **CVE-2022-22968:** Spring 데이터 바인딩의 대소문자 구분 취약점을 악용하여 `setDisallowedFields` 임시 완화 조치 무력화.
  * **CVE-2022-22963:** Spring Cloud Function SpEL RCE 취약점을 Fallback 페이로드로 동시 공격.

## 7-2. 시나리오 재현 (공격 흐름 및 시뮬레이션 로직)
| 단계 | 공격 액션 (Attacker/System) |
|---|---|
| 1. 워터홀 노출 | 사내 관리자 페이지에 XSS를 주입하여 "Spring 프레임워크 긴급 패치 권고" 위장 모달 팝업 렌더링. |
| 2. 다형성 페이로드 | 관리자 클릭 시 백그라운드 JS가 작동하여, `fullhunt/spring4shell-scan`에서 추출한 WAF 우회 문자열(예: `Class.*`, `*.class.*` 변조)을 포함한 POST 요청 전송. |
| 3. 완화 조치 우회 | `setDisallowedFields`로 방어된 서버를 뚫기 위해 대소문자 속성 체인을 변조(CVE-2022-22968)하여 Tomcat AccessLogValve 조작 성공. |
| 4. 정보 자동 추출 | 웹쉘 설치 직후 `SpringBoot-Exploit-Toolkit` 기법을 사용하여 Spring Actuator 노출 정보를 스캔하고 AWS/클라우드 토큰 탈취. |

## 7-3. 대응 방안
* **코드 레벨 패치:** 우회 가능한 블랙리스트 조치에 의존하지 않고, 즉시 Spring Framework 5.3.19 이상으로 업데이트하여 CVE-2022-22968 우회 공격 원천 차단.
* **행위 기반 탐지:** WAF 시그니처 우회를 대비하여, Tomcat `webapps/ROOT` 내 비정상적인 파일 생성 행위를 EDR로 실시간 탐지 및 차단.
