본 보고서는 Spring4Shell(CVE-2022-22965)을 거점으로, TeamCity(CVE-2024-27198)와 Struts2(CVE-2023-50164)로 횡적 이동을 연계 수행하고 사내망 기밀 NAS 데이터를 탈취하는 APT 모의해킹 통합 시나리오 결과를 기록합니다.

공격 대상 서버 주소: http://localhost:8011/spring-form/login

거점 웹쉘 주소: http://localhost:8011/health_check.jsp?pwd=glory&cmd=id

최종 실습 판정: 전체 시나리오 장악 성공

단계별 해킹 수행 상세 내역

✅ 성공 STEP 1 | Payload Transmission

Payload Transmission: Spring Framework의 Data Binding 취약점을 이용해 Tomcat 로그 기록 속성을 외부에서 변조하는 패킷을 전송했습니다.

타겟: http://localhost:8011/spring-form/login
Spring Data Binding 취약점(CVE-2022-22965)을 이용해 Tomcat AccessLogValve 속성 변조 페이로드를 성공적으로 전송했습니다.

✅ 성공 STEP 2 | Tomcat Log Flush

Tomcat Log Flush: 물리 디스크에 yaho4.jsp 웹쉘이 생성되도록 유도 트래픽을 보냈습니다.

GET http://localhost:8011/spring-form/login → HTTP 200
Tomcat AccessLog 버퍼가 비워지면서 페이로드 코드가 yaho4.jsp 파일로 디스크에 기록됩니다.

✅ 성공 STEP 3 | Stage1 (yaho4.jsp) Verified

1단계 웹쉘(Stager) 접속 상태를 점검하여, 타겟 서버의 코드 실행(RCE) 권한 획득 여부를 검증했습니다.

웹쉘 URL: http://localhost:8011/yaho4.jsp?cmd=whoami

확인 로그:
[1/5] yaho4.jsp?cmd=whoami → root

✅ 성공 STEP 4 | Stage2 Deployed (curl or docker cp)

기본 웹쉘을 거점 삼아, 향후 횡적 이동의 중추가 될 완성형 Stage2 웹쉘(health_check.jsp)을 내부 배포했습니다.

[A] curl 방식으로 health_check.jsp 배포 성공

✅ 성공 STEP 5 | Stage2 (health_check.jsp) Verified

디버깅과 원활한 RCE 로직을 탑재한 완성형 웹쉘의 동작 무결성을 점검했습니다.

웹쉘 URL: http://localhost:8011/health_check.jsp?pwd=glory&cmd=id

✅ 성공 STEP 6 | Info Leakage (Find DB Clients & Configs via RCE)

Info Leakage (크리덴셜 추출): RCE를 활용하여 타겟 환경 내부에 저장된 DB URL 및 계정 정보를 탐색해 성공적으로 탈취했습니다.

발견된 DB 클라이언트: mysql, psql, sqlite3

설정 파일: /usr/local/tomcat/webapps/spring-form/WEB-INF/classes/application.properties

  • DB URL : jdbc:mysql://spring-db:3306/spring_db?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC
  • USER : spring_user
  • PASS : spring_pass
